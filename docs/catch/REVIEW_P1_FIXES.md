- **Shop and Wallet are now real** (`modules/catch_shop.py`, `discord_bot/cogs/_views_catch_shop.py`, `tests/unit/test_catch_shop.py`). Shop: pick an item from `CATALOG` (basic/sturdy/prime capsule, honeyberry, goldberry; the sovereign capsule is never sold), then press a Buy x1/x5/x10 button that shows its total price. `purchase()` is the only code that spends coins: one transaction with a guarded `UPDATE ... WHERE coins >= total` (row lock, so concurrent buys serialise), the item grant, and a `shop_purchase` audit row; the price always comes from the catalog, never from the client. The view re-checks the `shop` gate on every buy, only accepts clicks from its owner, and ignores a second click while a purchase is running. (Creature sales were added afterwards; see the Sell paragraph below.)
- **Sell is now real** (`modules/catch_sell.py`, `discord_bot/cogs/_views_catch_sell.py`, `tests/unit/test_catch_sell.py`). The Economy > Sell screen lists the player's creatures that are not favourites and not locked (10 per page, newest first), shows what each sells for, and needs a select plus an explicit **Sell for N coins** press (Cancel clears the choice). `sell_creature()` is the only code that pays coins for a creature: one transaction with `SELECT ... FOR UPDATE` on the creature row scoped by id, user_id and clone_key in SQL, refusal of favourites and locked creatures, `DELETE ... RETURNING id` (coins are credited only if the row was really deleted, so a lost race pays nothing), the coin credit, and a `sell` audit row. If the player row is missing the transaction raises and rolls back, so a creature is never deleted unpaid. The value comes from the species rarity (`Rarity.sell_value`: common 10, uncommon 30, rare 120, epic 500, mythic 2500) times 5 for shiny or 10 for special (special beats shiny; they never stack); the client never sends a price and a species that cannot be priced is never offered. Wallet now lists sales as positive lines. The view re-checks the `shop` gate on every sale, is owner-only, and ignores a second click while a sale is running. Real-Postgres test (`test_sell_concurrent_taps_pay_once_and_protect_favourites_and_other_players`): six overlapping sells (held behind a row lock, then released together) pay exactly once; favourite, locked, another player's and wrong-clone creatures are refused unchanged; a missing player row rolls the sale back. Removing both the row lock and the DELETE check makes that test fail (`assert 6 == 1`). Not done: sell-all / bulk sell, selling items, and any refund. Values are balance numbers for P11-06.
